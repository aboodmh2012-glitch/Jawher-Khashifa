# خريطة دمج Fusion Travel — Odoo 19

## 1. المصدر الأساسي لكل جزء

### موديول GitHub الحالي `fusion_travel`
يُستخدم كأساس للوظائف المالية والتشغيلية الموجودة مسبقًا:
- شركات الطيران وأكواد IATA والتذاكر.
- عمليات الإصدار، التغيير، الاسترجاع والإلغاء.
- ربط التذاكر بالفواتير والحسابات.
- إعدادات المنتج الافتراضي وربط `account.move`.

### ملف الباك إند المرفوع `trip`
تم إدخال مكوناته داخل نفس namespace باسم `fusion.travel.*`:
- الحجز الموحد للرحلات والفنادق وخدمات المركبات/التحويلات.
- المسافرين ومقاطع الرحلة والإقامة الفندقية.
- قواعد التسعير والعمولة والـmarkup.
- المحفظة التشغيلية وسجل استدعاءات الـAPI.
- خدمات Amadeus للرحلات والفنادق والتحويلات.
- جلسات بحث وعروض قصيرة العمر محفوظة في الخادم.

### واجهات Figma
تم تحويل الهوية والأسلوب العام إلى QWeb + SCSS داخل Odoo Website:
- شاشات البحث.
- نتائج الرحلات والفنادق وخدمات المركبات.
- بيانات المسافر/الضيف.
- إعادة التحقق من السعر.
- الدفع والتأكيد.
- بوابة العميل لمشاهدة الحجوزات.

## 2. مسار البيانات الموحد

1. المستخدم يبحث من `/travel/...`.
2. Odoo يستدعي مزود الخدمة من طبقة `services/`.
3. يتم حفظ العرض في `fusion.travel.offer` برمز opaque بدل إرسال payload موثوق للمتصفح.
4. عند الاختيار، ينشأ `fusion.travel.booking` ويُربط بالعميل والوكيل والشركة.
5. تُجمع بيانات المسافرين أو الضيوف.
6. يعاد تسعير العرض قبل الدفع عند توفر endpoint لذلك.
7. يتم الدفع بالمحفظة أو عبر تدفق بطاقة مستضاف/مرمّز.
8. ينشأ طلب المورد ويحفظ رقم PNR أو التأكيد.
9. ينشأ سجل التذكرة أو الحجز ويُرسل إلى المحاسبة والبوابة.

## 3. حدود النسخة الحالية

- ملف `amadeus_cars.py` في الباك إند المرفوع يعالج Amadeus Transfers، وليس مخزون تأجير سيارات ذاتي كامل؛ لذلك لا ينبغي عرض extras وتأمينات تأجير ذاتي قبل إضافة مزود فعلي.
- لا تُجمع أرقام بطاقات أو CVV الخام داخل Odoo؛ يجب ربط Hosted Checkout أو tokenization.
- يلزم اختبار تثبيت وتشغيل على نسخة Odoo 19 الفعلية وقاعدة تجريبية قبل الدمج في الإنتاج.
- بعض شاشات Figma مثل Map View وتفاصيل extras الكاملة تبقى مرحلة ثانية حسب الـAPI المتاح.

## 5. الصلاحيات

- Travel User: تشغيل الحجوزات المسندة إليه.
- Travel Accountant: مراجعة المدفوعات والمحفظة والتذاكر.
- Travel Manager: كامل الإعدادات والإلغاء وإدارة السجلات.
- Portal User: قراءة حجوزاته ومسافريه ووثائقه فقط.
