# منصة العمليات — المواصفة الموحدة للوصول إلى الإصدار النهائي

التاريخ: 7 سبتمبر 2026. المستودع: aboodmh2012-glitch/Jawher-Khashifa.
هذه مواصفة هدف وخطة تنفيذ مبنية على سياق المحادثات المتاح وفحص الكود الحالي؛ ليست شهادة بأن جميع مكوناتها نُفذت. نتيجة التنفيذ الفعلي وحدوده في RELEASE_READINESS.md.

## القرار المعماري

نبقي المشروع الحالي ونطوره تدريجيًا إلى منصة معلومات عمليات، إدارة حوادث، بحث وإنقاذ، أساطيل، حساسات، خرائط واتصالات. نحافظ على Monorepo وshared contracts وAdapter SDK وSkynode وMAVLink وTAK/CoT وVideo وRawEvent وسجل القياسات ومركز العمليات.

نقسم المنتج إلى ثلاث طبقات، مع مساعد متخصص مستقل:

| الطبقة | المسؤولية | الحد الفاصل |
|---|---|---|
| Platform Core | الهوية والصلاحيات والبيانات والحوادث والمهام والخريطة والتدقيق | مصدر حقيقة واحد وعقود مستقرة |
| Edge Runtime | استقبال المصادر والتحقق منها وحفظ الرسائل عند انقطاع الشبكة | لا يعتمد على استمرار اتصال المركز |
| App Ecosystem | تطبيقات وإضافات محددة الصلاحيات لكل وظيفة | لا وصول مباشر لقاعدة البيانات أو الأسرار |
| Intelligence Service | تفسير بيانات التشغيل وإعداد ملخصات موثقة | قراءة فقط؛ بدون تنفيذ أوامر أو تغيير سجلات |

المنصة الحالية ذات استخدام مدني. لا تشمل تعيين الأسلحة أو التحكم بها أو إطلاقها أو استهدافًا آليًا أو تسلسل اشتباك أو هجومًا مستقلًا. دعم القرار محصور في السلامة والحوادث وحالة الموارد وثقة المصادر وجودة البيانات وتوصيات المشغل.

## دورة البيانات المعتمدة

1. تصل رسالة المصدر مع هويته ووقت الاستقبال.
2. تحفظ RawEvent قبل التطبيع وقبل نشر الحدث على الحافلة.
3. يتحقق parser محدد الإصدار من البنية والمجال والوحدات؛ الرسائل غير الصالحة تحفظ في quarantine مع السبب.
4. تنتج قياسات موحدة مع source timestamp وreceived timestamp وcorrelation ID ومصدر البيانات.
5. يحفظ التاريخ بصورة مستقلة عن الحالة الحالية؛ الرسالة المتأخرة لا تعيد الحالة إلى الوراء.
6. تثبت المعاملة وتكتب outbox، ثم ينشر الحدث بقابلية إعادة المحاولة وإزالة التكرار.
7. تتحدث الخريطة والتنبيهات والحوادث والملخص التشغيلي عبر اشتراكات مصرح بها.
8. عند إعادة الاتصال يتلقى العميل snapshot متسقًا وcursor، ثم التغيرات التالية له. عند انتهاء صلاحية cursor يطلب snapshot جديدًا.

التنفيذ الحالي يحقق ترتيب RawEvent، ربط correlation، حماية الحالة من البيانات المتأخرة، وحفظ checkpoint. outbox وcursor وإعادة المعالجة الآلية أهداف لم تنفذ بعد.

## الوظائف المطلوبة للمنتج النهائي

| الوحدة | ما يجب أن ينجزه المستخدم | شرط القبول |
|---|---|---|
| مركز العمليات | رؤية الموارد والحوادث والتنبيهات ذات الأولوية | كل مؤشر له مصدر ووقت تحديث وحالة اتصال |
| الخريطة | تشغيل طبقات وأصول ومسارات ومناطق وملاحظات | هندسة صحيحة وإصدارات تمنع الكتابة فوق تعديل آخر |
| العمليات | إنشاء عملية وتحديد نطاقها وفريقها ومواردها وفترتها | كل سجل تابع للعملية يخضع لصلاحياتها |
| الأصول والأجهزة | تسجيل الجهاز وربطه بأصل وفحص سلامته واتصاله | فصل هوية الجهاز عن الأصل وعن مصدر القياس |
| القياسات | عرض الحالة الحالية وتاريخ القياسات وقنواتها ووحداتها | منع خلط الوحدات والمصادر والأزمنة |
| الحوادث | إنشاء الحادث وتصنيفه وتكليف فريق وتوثيق تطوره وإغلاقه | انتقالات حالة معتمدة ومرفقات وتدقيق |
| المهام | إنشاء مهمة مدنية وإسنادها ومتابعة موعدها وإنجازها | ضبط الصلاحية والتعارض والمواعيد |
| التنبيهات | استلام تنبيه وتأكيده وتصعيده ومعرفة زوال سببه | إزالة التكرار وإعادة فتح التنبيه عند التصعيد |
| الاتصالات | غرف عمليات وحوادث وفرق وصوت ورسائل وموقع اختياري | عضوية وصلاحيات وأرشفة وفق السياسة |
| الفيديو | عرض بث مصرح وربطه بالجهاز والوقت والخريطة | رموز قصيرة العمر ومنع تسريب عنوان المصدر وكلمة مروره |
| التاريخ وإعادة العرض | استعراض حالة سابقة وتزامن الخريطة والقياسات والأحداث | الزمن التاريخي واضح ومنفصل عن التشغيل الحي |
| العمل دون اتصال | قراءة البيانات المصرح بتخزينها وحفظ تعديلات محلية | مزامنة قابلة للاستئناف مع سياسة تعارض وحذف واضحة |
| التكاملات | معرفة ما هو متصل أو محاكاة أو غير مطبق | حالة فعلية، آخر اتصال، خطأ مفهوم وخطوة إصلاح |
| المساعد المتخصص | سؤال عن حالة التشغيل والحصول على إجابة موثقة | مصادر، نطاق صلاحية، وإقرار بنقص المعلومات |
| الإدارة | إدارة الهوية والعضوية والأجهزة والإعدادات | لا تعديل صلاحيات من واجهات المشغل |
| التدقيق | معرفة من فعل ماذا ومتى وبأي نتيجة | سجلات قابلة للبحث ومحمية من التعديل |

واجهة عربية/إنجليزية مع RTL، بحث موحد، اختصارات لوحة مفاتيح، حالات تحميل/فراغ/فشل واضحة، وتخطيط مناسب للشاشات الكبيرة والجوال. الهاتف يركز على المهام والبلاغات والاتصال؛ مركز العمليات يعرض الصورة الكاملة وفق صلاحيات المستخدم.

| المجال | الاتجاه المعتمد | مبرر الاختيار وحدوده |

| سجل القياسات | PostgreSQL أولًا؛ TimescaleDB بعد قياس الحاجة | لا نضيف قاعدة أخرى بلا مبرر حجم واحتفاظ واستعلامات |
| الأحداث الموثوقة | NATS JetStream عند مرحلة النقل الموزع | بقاء الرسائل وإعادة العرض؛ يحتاج idempotency ولا يحل معاملات قاعدة البيانات وحده |

| الاتصالات والفيديو | مزود مستقل خلف provider contract | اختيار الخادم بعد تثبيت متطلبات الصوت والتسجيل والنطاق والتراخيص |
| الذكاء المحلي | llama.cpp في خدمة مستقلة | محرك تشغيل للنموذج، وليس نموذجًا متخصصًا جاهزًا بحد ذاته |

الاختيارات أعلاه قرارات تصميم لهذه المنصة وليست ادعاء أنها الأفضل لكل منتج. المراجع الرسمية وروابطها في RELEASE_READINESS.md. لم ننزل أوزان نموذج ذكاء أو نختبرها في هذه الزيادة.

## كيف يكون الذكاء «خاصًا بنا»

لا يكفي تثبيت مكتبة للحصول على ذكاء يعرف العمل. نبني حزمة محددة:

- محرك استدلال محلي منفصل عبر llama.cpp، بعنوان يضبطه المسؤول فقط.
- نموذج بترخيص مناسب، يختار بعد قياس جودة العربية والاستنتاج من سجلات التشغيل وزمن الاستجابة وذاكرة الجهاز.
- قاعدة معرفة من وثائقنا المعتمدة ومصطلحات المنصة وإجراءات الحوادث والأجهزة؛ كل نسخة تحمل مصدرًا وتاريخًا.
- أدوات قراءة مسموحة فقط: حالة الأصل، سجل القياسات، التنبيهات، الحوادث، المهام، البحث في الوثائق. لا أدوات أوامر للأجهزة أو تغيير صلاحيات أو تنفيذ تعليمات.
- استرجاع مقيد بالمنظمة والعملية وصلاحية المستخدم قبل إرسال المحتوى للنموذج؛ ليس الاعتماد على التعليمات النصية وحدها.
- إجابة منظمة: النتيجة، الأدلة وروابط السجلات، وقت صلاحية البيانات، ما هو مجهول، واقتراح مراجعة بشرية.
- قواعد موثوقة للحسابات والحدود والتنبيهات؛ النموذج يصوغ التفسير ولا يخترع أرقام القياسات.
- اختبار حالات باللغة العربية: بيانات ناقصة ومتعارضة وقديمة، سؤال خارج المجال، تعليمات خبيثة داخل مستند، وطلب الوصول لمنظمة أخرى.
- عند تعطل النموذج تستمر المنصة وقواعد التنبيه. لا تصبح خدمة الذكاء شرطًا لرؤية الخريطة أو تسجيل حادث.

منفذ الآن: Operations brief بقواعد صريحة مرتبطة بالسجلات. المتبقي: تشغيل النموذج، استرجاع الوثائق، واجهة الأسئلة، وتقييم الإجابات. لا نطلق على القواعد الحالية نموذج ذكاء خاصًا.

## حدود التطبيقات والتشغيل الميداني

App manifest يحدد الاسم والإصدار والتوافق والناشر والنقاط التي يضيفها التطبيق والصلاحيات المطلوبة. صلاحيات نموذجية: assets.read وtelemetry.read وincidents.read وincidents.write وmap.features.write. يمنح المسؤول أقل صلاحية لازمة، ويظهر سجل للتثبيت والترقية والتراجع.

الإضافة تعمل في عملية أو حاوية مستقلة، بحدود للذاكرة والمعالج والطلبات. توقيع الحزمة والتحقق من مصدرها يسبقان التحميل. لا ينفذ Core شيفرة غير موثوقة في عمليته. العقود والاختبارات تسبق إنشاء متجر تطبيقات.

Edge Runtime يحتاج هوية جهاز وشهادة قابلة للتدوير، سجلًا محليًا متينًا، قائمة انتظار محدودة، إعادة إرسال بمعرف ثابت، مقياس مساحة التخزين، وأولوية لسلامة النظام عند امتلائه. لا تعني خاصية إعادة اتصال المتصفح أن المزامنة الميدانية مكتملة.

## ترتيب التنفيذ الموحد

هذا ترتيب تنفيذي موحد يحافظ على القرارات الظاهرة في المحادثات: contracts أولًا، RawEvent قبل bus، والمزامنة بعد استقرار realtime وlocal store. التدقيق يرافق كل خطوة ثم يراجع نهائيًا في الخطوة الأخيرة.

|---|---|---|
| 1 | Contracts وإصداراتها | توافق المنتج والمستهلك |
| 2 | الهوية والنطاق والصلاحيات | رفض الوصول بين النطاقات |
| 3 | Schema ومخطط الترحيلات | ترقية وتراجع وقيود مرجعية |
| 4 | RawEvent journal | حفظ المصدر قبل الاشتقاق والنشر |
| 5 | Event bus + outbox | استعادة بعد الانقطاع وإزالة التكرار |

## تعريف «نهائي»

لا يكفي نجاح البناء أو جمال الواجهة. الإصدار النهائي يجب أن يمر بهذه البوابات:

1. كل وظيفة معلنة لها مسار مستخدم مكتمل؛ الوظائف غير المتصلة موسومة بوضوح.
2. اختبار حرمان الصلاحيات عبر REST وWebSocket والتاريخ والفيديو والإضافات والذكاء.
3. حفظ معاملات موثوق، إثبات استرجاع نسخة احتياطية، وتجربة تعطل عملية ونقل شبكة وانتهاء جلسة.
4. أهداف حمل محددة بعد معرفة عدد الأجهزة ومعدل الرسائل وعدد المشغلين ومدة الاحتفاظ؛ النتائج تقاس ولا تخمّن.
5. تكاملات حقيقية قابلة لإعادة الاختبار؛ المحاكاة لا تعتبر إثبات تكامل جهاز.
6. اختبار واجهة عربية وإنجليزية، جوال، RTL، لوحة مفاتيح، وأخطاء الشبكة.
7. سياسات أسرار وشهادات وتحديثات واعتماديات واحتفاظ وتدقيق، مع دليل تشغيل واستجابة للأعطال.
8. مساعد متخصص يجتاز اختبارات النطاق والأدلة والصلاحيات؛ لا يتجاوز القواعد أو ينفذ قرارات.

## ما أنجز في هذه الزيادة

تم تحسين الكود مباشرة، مع المحافظة على بنية المستودع: دخول آمن للبيئة التجريبية، OIDC/PKCE، مصادقة WebSocket، تحقق حدود المنظمة، مخططات الطلبات، منع الكتابة المتعارضة للميزات، إصلاح ترتيب القياسات والتنبيهات، حفظ حالة وأرشيف محلي، ربط المصادر، وملخص تشغيلي قابل للعرض.

نجاح 12 اختبارًا وفحص TypeScript والبناء دليل على هذه الزيادة فقط. قاعدة البيانات الموزعة، المزامنة، متجر التطبيقات، التكاملات الحية، والذكاء المحلي تبقى أعمالًا تنفيذية مطلوبة قبل تسمية المنتج «نهائيًا».
